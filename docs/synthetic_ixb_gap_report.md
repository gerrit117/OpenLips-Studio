# Synthetic IXB Gap Report

This report compares a known-working local DLC-style sample pair against the
current from-scratch synthetic IXB pair generated by
`tools/build_minimal_ixb_pair.py`.

The comparison is semantic rather than a raw byte diff. It focuses on schema
inventory, resource ownership, chart roots, marker relationships, and likely
minimum structures needed before a fully standalone synthetic chart can load in
Lips.

## Comparison Inputs

Local comparison command:

```powershell
py tools\compare_ixb_structure.py `
  --real-chart private\samples\charts\1234.X360 `
  --real-lyric private\samples\lyrics\1234_Lyric.X360 `
  --synthetic-chart private\outputs\minimal_ixb\1234.X360 `
  --synthetic-lyric private\outputs\minimal_ixb\1234_Lyric.X360
```

High-level result:

| File | Real | Synthetic |
| --- | ---: | ---: |
| chart size | 571,977 bytes | 1,790 bytes |
| lyric size | 5,158 bytes | 468 bytes |
| chart `NumOfElements` | 2,913 | missing |
| lyric `NumOfElements` | 12 | missing |
| chart class count | 59 | 8 |
| lyric class count | 15 | 3 |
| MelodyMarkers | 683 | 3 |
| LyricMarkers | 653 | 3 |
| lyric Text resources | 2 | 1 |

## Major Missing Structures

### Package Graph

The real chart and lyric schemas include a package tree/list/vector layer:

- `ixTreeNode<ixPackage>`
- `ixPackage`
- `ixList<ixPackage *,ixAllocator<ixDblCnt<ixPackage *>,1> >`
- `ixVector<ixPackage *,1,ixAllocator<ixPackage *,1>,ixIterator<ixPackage *> >`
- `ixDblCnt<ixPackage *>`

The synthetic pair currently has only a single empty `ixPackage` object. Its
fields are essentially zeroed, so it does not model package name storage,
children, linked packages, packed size, or package vectors.

### Asset And Resource Graph

The real lyric file defines and uses:

- `ixAssetPackage`
- `ixAsset`
- `ixFileImage`
- `ixRawFileImage`
- `ixVector<char,1,ixAllocator<char,1>,ixIterator<char> >`
- `ixVector<ixAsset *,1,ixAllocator<ixAsset *,1>,ixIterator<ixAsset *> >`

The synthetic lyric file has a valid-looking `Text` byte payload, but it is not
owned by an `ixRawFileImage` / `ixFileImage` / `ixAsset` chain. This is the
strongest current explanation for why the synthetic file is readable by our
heuristics but rejected by the game.

### Chart Roots And Sequences

The real chart schema includes chart and sequence ownership objects that the
synthetic chart does not model:

- `ixChart`
- `lpsChart`
- `ixSequence`
- `ixTempoMap`
- `lpsMusicInfo`
- `lpsMusicIndex`
- sequence vectors such as `ixVector<ixSequence *>` and `ixVector<ixSeqCode *>`
- marker families beyond melody/lyric, including phrase, page break, hit, and
  short-end markers

The synthetic chart currently contains only three MelodyMarkers, three
LyricMarkers, and three WordData records. It has no chart root telling Lips what
the playable sequences are.

## Marker Encoding Difference

The real sample exposes marker records with file-layout tags:

| Marker | Real tags | Synthetic tags |
| --- | --- | --- |
| `lpsMelodyMarker` | `0x28` | `0x05` |
| `lpsLyricMarker` | `0x40` | `0x07` |

In the real chart, `lpsMelodyMarker` has schema index `0x25` and size `0x28`,
while the actual marker records use `0x28`. `lpsLyricMarker` has schema index
`0x26` and size `0x40`, while records use `0x40`.

The synthetic builder currently writes schema indices as object tags. That is
accepted by our current walker because it includes schema-index fallback, but it
does not match the real file-layout encoding the game appears to consume.

## Lyric Resource Selection

The real lyric file has two `Text` resources:

- visible lyric payload: selected by chart WordData coverage, 653/653 markers
- small mostly-binary Text resource: low WordData coverage

The synthetic lyric has one `Text` resource and it has full WordData coverage,
but coverage alone is not enough. The resource also needs to be connected to the
package/asset/file-image graph.

## Mode And Duplicate Group Clues

The real chart has many duplicate timing groups:

- duplicate MelodyMarker time groups: 300
- duplicate LyricMarker time groups: 285

The synthetic chart has no duplicate timing groups. This supports the existing
hypothesis that real charts may contain multiple synchronized groups for modes,
players, short/full versions, or other sequence variants. A tiny standalone
chart may need at least a minimal valid sequence set, not just one marker list.

## Minimum Next Structures To Model

1. Recreate the real IXB header metadata, especially `NumOfElements`.
2. Serialize package objects in the same file-layout style as real files,
   including package tree/list/vector fields.
3. Add `ixAssetPackage` and asset vectors for both chart and lyric files.
4. Store lyric `Text` as an `ixRawFileImage` / `ixFileImage` asset, not as a
   naked inline payload.
5. Add chart root objects: `lpsChart` / `ixChart`, `ixSequence` containers,
   tempo map, music info/index, and sequence vectors.
6. Encode MelodyMarker and LyricMarker records with real file tags (`0x28`,
   `0x40`) and pointer/reference style.
7. Validate:
   - `LyricMarker -> MelodyMarker`
   - `LyricMarker -> LyricWordData vector`
   - `LyricWordData -> selected Text payload`
   - asset package vectors and resource ownership
8. Decide which duplicate marker or sequence groups are required for single,
   VS, duet, short, and full modes before attempting the next tiny playable
   synthetic chart.

## Current Conclusion

The current synthetic pair is not wrong because of lyric text encoding or marker
timing. It is incomplete as an IXB object graph. The next synthetic writer should
not add more raw marker records first; it should build the package, asset, raw
file image, chart root, and sequence ownership layers that real DLC files
contain.

## Minimal Ownership Iteration

The next builder iteration intentionally does only the smallest runtime-facing
step before full chart reconstruction:

- MelodyMarker records now emit tag `0x28`, matching the real file-layout tag.
- LyricMarker records now emit tag `0x40`, matching the real file-layout tag.
- Chart and lyric headers now include `NumOfElements`.
- The lyric schema now includes the same package/asset/file-image class
  inventory as the real `1234_Lyric.X360` sample.
- The lyric file now emits a minimal chain:
  `ixPackage -> ixAssetPackage -> ixAsset/ixFileImage/ixRawFileImage -> Text`.
- The Text payload is still selected by chart LyricWordData coverage.

Fresh comparison against the real `1234` pair now shows:

| Item | Real | Synthetic minimal ownership |
| --- | ---: | ---: |
| chart `NumOfElements` | 2,913 | 18 |
| lyric `NumOfElements` | 12 | 14 |
| chart class count | 59 | 20 |
| lyric class count | 15 | 15 |
| MelodyMarker tags | `0x28` | `0x28` |
| LyricMarker tags | `0x40` | `0x40` |
| visible Text coverage | 653/653 | 3/3 |

Remaining structural gaps after this minimal step are now concentrated in the
chart root/sequence layer:

- `lpsChart` / `ixChart`
- `ixSequence`
- `ixTempoMap`
- `lpsMusicInfo` / `lpsMusicIndex`
- `ixVector<ixSeqCode *>`
- `ixVector<lpsLyricWordData>`
- phrase/page/hit/short-end marker families

This gives a cleaner in-game test boundary. If the minimal ownership pair still
crashes, the next smallest likely step is adding one valid chart root and one
sequence owner, not jumping directly to full duplicate mode reconstruction.

## Controlled Crash-Isolation Variants

After the minimal ownership pair hard-crashed the game, the builder was split
into controlled levels so each in-game test changes only one layer:

| Level | Marker tags | `NumOfElements` | Lyric ownership | Chart ownership |
| --- | --- | --- | --- | --- |
| `bare` | schema-index tags (`0x05` / `0x07`) | no | no | no |
| `tags` | real file-layout tags (`0x28` / `0x40`) | yes | no | no |
| `lyric-ownership` | real file-layout tags | yes | yes | no |
| `full-current` | real file-layout tags | yes | yes | yes |

Generation command for all local variants:

```powershell
py tools\build_minimal_ixb_pair.py `
  --synthetic-level all `
  --out-dir private\outputs\minimal_ixb_variants `
  --stem 1234 `
  --force `
  --compare-real-lyric private\samples\lyrics\1234_Lyric.X360
```

Each level writes a pair under:

```text
private/outputs/minimal_ixb_variants/<level>/1234.X360
private/outputs/minimal_ixb_variants/<level>/1234_Lyric.X360
```

The debug output prints:

- object tags
- `NumOfElements`
- class inventory
- package/asset/file-image counts
- ownership/vector field scans
- zero/null pointer-like fields
- Text resource chain summary
- an ownership-focused comparison against a real lyric file when
  `--compare-real-lyric` is provided

The current suspicion is that the hard crash is more likely caused by malformed
ownership vector/list fields than by melody timing or lyric text. The variant
matrix should identify whether the crash begins at `tags`, `lyric-ownership`,
or `full-current`.
